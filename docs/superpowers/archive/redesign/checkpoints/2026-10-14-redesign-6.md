# Checkpoint 6: Phone layouts

[PR #33](https://github.com/M4stas/kontroll/pull/33). Merged; the user tested and accepted it. The implementation follows the [plan](../plans/2026-10-14-redesign-checkpoint-6.md) and approved choices **1A, 2A, 3A, 4B, 5A**. The user also requested hidden scrollbar tracks on phones; native scrolling remains enabled. No work on checkpoint 7 is included.

## What you will see

At widths up to 639px, a compact header, swipeable listing photos with a count, fixed listing/review actions, and report cards with internal vertical scrolling. Back, dots and Next sit below the cards in page flow (approved 4B). Diagnostics opens as a full-screen sheet. Evidence and the full report use one column. The existing layouts apply from 640px upward.

## How to check

1. Start the app from this worktree, or open the running production preview at `http://localhost:3067/en` (ET: `/et`). For a phone on the same network, use this computer's LAN address with port 3067.
2. Submit either approved listing: [Audi](https://www.auto24.ee/soidukid/4028601) or [Peugeot](https://www.auto24.ee/soidukid/4355947). Swipe photos and expand listing details. Check that the bottom actions leave the final content reachable.
3. Start a review with the local analysis worker running. Scroll its photos, then open the completed report. It should start at the cover.
4. Swipe cards, scroll long content inside a card, use Back/Next and the dots, copy the seller message, and tick checklist items. Open evidence, Full report and diagnostics.
5. Repeat on real phones in EN and ET, light and dark, including landscape. Check safe areas, keyboard behavior and native scrolling. Theme and real-device acceptance remain with the user; nothing is merged.
