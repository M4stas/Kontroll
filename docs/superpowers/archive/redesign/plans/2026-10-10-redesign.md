# Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the approved redesign demo into the real app: new visual system, new start and listing page layouts, and the report as a row of cards with a full-report section below.

**Architecture:** Checkpoint 1 swaps the design tokens, font and shared header for every page at once, keeping layouts. Checkpoints 2 to 5 rebuild one surface each on top of those tokens. Report logic that decides what to show (finding selection, seller message text, activity state) moves into pure modules with their own tests, and the new components only lay that data out.

**Tech Stack:** Next.js 16 App Router, React 19, next-intl, Tailwind 4 with plain CSS, `next/font/google`, `@phosphor-icons/react`, `@base-ui/react` Dialog, Vitest with Testing Library. No new dependencies.

**Spec:** [Redesign design](../../../specs/2026-10-10-redesign-design.md). Reference demo: `demos/redesign/final/`.

## Global Constraints

- Follow the [development agent policy](../../../../agent-policy.md) for models and delegation. Do not repeat its table here.
- Read the relevant guide in `node_modules/next/dist/docs/` before writing Next.js code. Fonts: `01-app/01-getting-started/13-fonts.md`. Viewport: `01-app/03-api-reference/04-functions/generate-viewport.md`.
- All redesign work collects on the `redesign` branch. Each checkpoint gets its own branch from the latest `redesign` and its own PR into `redesign` with "What you will see", "How to check", "Verification" and "Screenshots" sections, a clean independent review, and the user's check in the running app. Never delete remote branches.
- Gates for every checkpoint: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`. The first build downloads Geist, so it needs network access.
- Every new string ships in `messages/en.json` and `messages/et.json` (or in `src/features/listing/messages.ts` for listing pages) in the same commit. Estonian is primary.
- UI copy uses no em dashes.
- Report-authored text (finding titles, explanations, action titles and instructions, evidence claims) keeps `lang={report.locale}`.
- Every finding in a report stays visible on a card or in the full report. Seller message and checklist render only when `showRecommendations` is true.
- `ReportView`'s `offline` prop keeps hiding refresh, diagnostics and every upload form. From checkpoint 4 it also hides retry.
- Desktop is the design target, 1280 to 1600px wide. At 390px wide every page must have no sideways scrolling and every control must stay reachable. Phone layouts are a later roadmap checkpoint.
- Light and dark follow `prefers-color-scheme`. Interactive elements are at least 44px tall, show a visible focus ring, and stop animating under `prefers-reduced-motion`.
- Each checkpoint deletes the CSS and components it replaced.
- Before opening each checkpoint PR, merge the latest `main` into `redesign` and then `redesign` into the checkpoint branch. Keep the diagnostics drawer's markup intact, because the diagnostics checkpoints build on it.
- After checkpoint 5 is accepted, one PR merges `redesign` into `main`.

## Review Focus

1. A report with no open findings, or with no seller or inspection actions, shows a cover that says so and no empty message or checklist card. Owner: Task 3.4, test `omits message and checklist cards when no actions apply`.
2. Long Estonian finding text and many critical findings (eight or more) must not be clipped. Cards grow instead of cutting text. Owner: Task 3.4, test `renders long finding text in full on its card`.
3. A running report refreshes itself through `ReportRefresh`. A refresh must not move the reader back to the cover. Owner: Task 3.3, test `keeps the current card when the card list re-renders with the same ids`.
4. A private photo that fails to load must leave a usable card: an area icon on finding cards, a plain cover. Owner: Task 3.4, test `falls back to the area icon when the finding photo fails`.
5. Keyboard users can reach every control in every card. Focusing a control inside an off-screen card must bring that card into view and mark it current. Owner: Task 3.3, test `marks the card current when focus moves into it`.

## Checkpoint 2: Start page and listing page

The steps for Codex agents are in the [checkpoint 2 plan](2026-10-11-redesign-checkpoint-2.md). It replaces Tasks 2.1 to 2.4 below, which stay as background.

### What you will see

The start page has a large left-aligned headline, the intro text and one pill-shaped address bar with the submit button inside it. The manual-entry option sits below. There is no photo.

The listing page has two columns. The left column shows the vehicle title and source, a three-step progress bar (Request received, Reading the listing, Details ready), the photos in a grid that fills in when the details arrive, then the description, equipment and technical details. The right column has a card that stays in view while you scroll, with the key facts and the button that starts the inspection report.

### How to check

1. Open `/et` and `/en`. The headline, intro and address bar show, with no photo.
2. Submit "not a link". The error shows under the bar in the attention color, and the field is marked invalid.
3. Press "Continue manually". The manual form opens below.
4. Submit a real Auto24 link. On the listing page the steps advance, and grey photo placeholders turn into the listing photos.
5. Scroll down. The facts card stays visible, and its "Open inspection report" button opens the report.
6. Open a capture that failed. The reading step shows in the attention color, with the existing failure message and the link to try another listing.
7. Repeat in dark mode and in Estonian.

## Checkpoint 3: Report cards

### What you will see

A report opens as a row of large cards. Move through them with Back and Next, the arrow keys, or a trackpad swipe:

- A cover with the verdict, the car's first photo and how many things to check.
- One card per main finding, with its photo or an area icon on the left, and on the right what was found and where it came from.
- A "Send it in one message" card with the seller message and a copy button.
- An "At the viewing" card where you tick off checks.

The older sections (all checks, sources, upload forms) still sit below the cards, in the new colors, until checkpoint 4.

### How to check

1. Open a complete report. The cover shows the vehicle line, the verdict, "N things to check before you go", the status and the confidence.
2. Move with Next and Back, with the arrow keys after clicking into the cards, and with the progress strip above them. The Next button names the next card.
3. Finding cards have no "next check" box. Their source line opens the evidence dialog with the photo or the quoted text.
4. The message card holds the same text the old seller message had. Copy works.
5. Tick checklist rows. The count updates. Reloading the page clears the ticks, because saving them comes with offline saving.
6. Open a report with no seller questions or inspection tasks. Those two cards are missing.
7. Open a report that is still running. The cover says "Checking the listing", there are no message or checklist cards, and the page's self-refresh does not jump back to the cover.
8. Switch the interface to Estonian on an English report, and the other way round. Report text keeps its own language.

## Checkpoint 4: Full report and the evidence row

### What you will see

Under the cards there is a slim row with "Seller replied or new photos?" and the taustakontroll PDF upload. Below it sits a closed "Full report" section. Opening it shows:

- every finding, grouped by area, with its next check and evidence;
- other and cleared observations;
- the per-photo review status;
- the listing facts, the sources and the methodology note.

All of it is in the new style. The message card's "Seller replied" button opens the same add-evidence dialog. The old layout below the cards is gone.

### How to check

1. Open a complete report. Below the cards, the add-evidence row is visible and "Full report" is closed.
2. Open "Full report". Each area shows its counts. Open an area: its findings show the explanation, "Next check" and the evidence dialog.
3. Compare with the same report on `main`. Every finding from the old "All checks" appears.
4. Press "Seller replied" on the message card, then the button in the row. Both open the dialog with the supplement form. Submit a seller answer. A new run starts at the same address, and the cover shows the checking state.
5. Upload a taustakontroll PDF from the row. Then try a locked or oversized PDF. The upload is rejected with the existing error.
6. Open a report whose review is incomplete and idle. The retry button sits in the row.
7. With `LIVE_DIAGNOSTICS_ENABLED=true`, the Live diagnostics button sits in the row and opens the drawer.
8. Repeat in dark mode and in Estonian.

## Checkpoint 5: Review step and design record

> Revised on 2026-10-11. The spec's decision 9 and its "Report" section replace the folding progress screen with a review view and an "Open the report" button. Task 5.1 below still describes the folding screen; rewrite it from the spec before starting this checkpoint.

### What you will see

While a report is being written, the report address shows the review view: the car's name, a three-part progress bar (Read listing, Review photos, Write review) that follows the real review progress, and the listing photos in a grid:

- waiting photos shimmer;
- reviewed photos appear in full;
- unavailable and skipped photos say so.

Below the grid, "Open the report" stays disabled until the review is complete. Pressing it shows the cards. A report that is already finished opens straight to the cards.

### How to check

1. Submit a listing with photos, start the report and watch the top of the page.
2. The steps advance, and the "x of y reviewed" count matches the grid.
3. Stop the worker during the review. After the lease expires, the stale or stopped message shows in the attention color. Restart the worker, and the review continues.
4. Turn on reduce motion. There is no shimmer and no fold animation.
5. Open a report whose listing has no photos. It says "No supplied photos" and shows no grid.
6. Open a finished report. Only the "Review complete" line sits above the cards.
7. Read `DESIGN.md`. It describes the new system.
