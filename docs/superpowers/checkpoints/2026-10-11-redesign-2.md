## Implementation decisions

- The approved checkpoint plan and current tokens take precedence over the older DESIGN.md palette. If this interpretation is wrong, the cost is visual rework.
- CaptureProgress accepts an optional outer data-state value so the existing connection warning retains its styling. If this is wrong, the cost is adjusting one prop.
- The task-brief helper recognizes Task headings, while the approved plan uses Step headings. Scratch briefs were extracted from the Step sections verbatim. If this is wrong, the cost is regenerating scratch files.

A fourth decision moved the final browser matrix to the successful production build after the transient empty dev manifest. If this is wrong, the cost is rerunning the matrix under dev after the manifest issue is resolved.

The design detector found four advisory differences against the older DESIGN.md type and radius scales. All four match explicit values in the approved plan. The existing design sidecar is also stale. This checkpoint does not refresh those files.

## Remaining scope

Report cards and dedicated phone layouts belong to later checkpoints. At 390px this checkpoint must keep controls reachable and avoid sideways scrolling. Checkpoint 3 has not started. Human PR review and user acceptance remain.
