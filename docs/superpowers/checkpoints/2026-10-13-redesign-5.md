## Browser checks

All checks used the production build and the real worker on real Auto24 listing `4344096` with 19 photos. The internal browser handled the first QA report and the interaction checks. Its screenshots come back at 800x500, so exact 1440x900 captures came from Brave in headless mode, driven over the DevTools protocol, on a second QA report. That browser also handled color scheme and reduced-motion emulation. Each language was captured in a tab at the front, because report refresh pauses in a background tab.

| How to check step | Result |
| --- | --- |
| 2. Bars and count | Read listing fills first; the "x of 19" count matched the reviewed tiles and loaded images (7 of 19, 10 of 19); Write review fills last |
| 3. Tiles | Waiting tiles shimmer; reviewed photos load; only reviewed tiles request images |
| 4. Open the report | Off while queued and running; on when the review ends, with "Your review is ready to read"; opens to "Review complete · 19 photos reviewed"; reload opens straight to the cards. The user repeated the press and reload |
| 5. Stale and resume | Worker killed with SIGKILL; after the lease expired the stale message showed in the attention color and the button turned on. The user confirmed that the cards showed under the stale message and stayed after the worker restarted |
